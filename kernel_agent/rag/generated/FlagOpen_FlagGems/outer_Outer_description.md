- kernel family: matrix outer product (vector × vector → dense matrix on Cambricon MLU)
- concise summary: The Triton kernel tiles the M×N result plane, loads the corresponding lhs and rhs vector slices, forms the rank-one product in registers, and streams the tile back to the output, reusing cached rhs blocks when the width is a power-of-two multiple of the tile size.
- detailed summary: `outer_kernel` determines the number of M- and N-tiles, assigns each program a subset via a strided loop over `total_tasks_num`, and for each tile loads a BLOCK_M slice of the lhs and a BLOCK_N slice of the rhs. If `NEED_LOOP_N` is false (i.e., N fits in one tile) it loads the rhs span once, otherwise it reloads per tile; in both cases it multiplies the broadcasted vectors to produce a BLOCK_M×BLOCK_N matrix and stores it with masks for tail tiles. The Python helper `outer_` allocates the output on the Cambricon device, builds a grid that balances tile counts with the available cores, and dispatches the Triton kernel, while the autograd forward simply validates input shapes, calls `outer_`, and caches the original vectors for backward.
