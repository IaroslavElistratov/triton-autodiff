- kernel family: rotary position embedding (varlen, GPT-J/NEOX styles with NOPE support)
- concise summary: The Triton kernel iterates over batches, heads, and token tiles, loads the required frequencies, constructs rotated companions according to GPT-J or NEOX layouts, and writes the sine/cosine-mixed outputs while optionally preserving non-rotated NOPE segments.
- detailed summary: `_rope_kernel_thd_fwd` derives each tile’s token range from `cu_seqlens`, computes cosine/sine angles (reusing front-half frequencies when requested), and loads the source activations with masks for ragged sequences. Depending on `rotate_style` it reshapes and flips the head-dimension pairs via helper routines to form the rotated view, applies `out = x·cos + x_rotated·sin`, and stores the results to either the same buffer (inplace) or a separate output. When `HAVE_NOPE` is true it also copies untouched halves before/after the rotated block, supporting NOPE-first layouts. Grid sizing over `(batch, head, token-block)` keeps the implementation efficient for variable-length batches.
