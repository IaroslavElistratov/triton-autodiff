- kernel family: Chunked retention (exponential-decay state with chunk fusion)
- concise summary: The forward kernel slides through BT-length segments, applying head-dependent decay factors to accumulate a retention state, uses it to mix queries with both historical state and current keys/values, and optionally persists the final state for the next call.
- detailed summary: `fused_chunk_retention_fwd_kernel` launches over (value tiles × key tiles × batch·head). For each chunk it loads BT×BK queries/keys and BT×BV values, computes decay coefficients `d_o`, `d_h`, and `d_s` from the per-head base `b_b`, and forms the block output as the sum of two pieces: `Q * state` (scaled by `d_o`) and `dot(Q,K)` masked by causal structure and weighted by `d_s`, multiplied by `V`. The retention state `b_h` is decayed by `d_b` and updated with `Kᵀ · (V * d_h)`; when an `initial_state` is provided, it seeds `b_h`, and when `output_final_state` is true the last state tile is stored to `final_state`. A safety branch (`CHECK`) handles Triton <2.2.0 by guarding the first iteration. The Python wrapper selects block sizes (BT=64 with power-of-two BK/BV ≤64), allocates per-key-tile output buffers, launches the kernel, sums the partial outputs across key tiles, and returns the final tensor plus optional final state.
