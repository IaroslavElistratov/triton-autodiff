- kernel family: Cross-state merge (2-direction variant combining paired scan buffers)
- concise summary: The forward kernel tiles space–channel blocks, fetches two directional scan outputs from `y`, and accumulates them into the merged tensor `x`, accommodating either channel-first or channel-last layouts.
- detailed summary: `triton_cross_scan_flex_k2` mirrors the four-direction version but only instantiates two traversal routes (`HWRoute0` forward and `HWRoute2` reverse, collapsed when `scans==1`). Each program in the `(NH*NW, NC, B)` grid controls one `(BH×BW)` tile and a chunk of channels, masks partial tiles at the image edges, and maps between the stored scan layout (`y_layout`) and the requested merge layout (`x_layout`). With `operation=1` in `_CrossMergeTritonFk2_forward`, the kernel iterates over the channel chunk, loads the two directional tiles from `y`, optionally handling the `one_by_one` format, sums them, and writes the result into `x`. The host code sets tile sizes (`BC=1`, `BH=BW=32`), allocates the output tensor either as `(B,C,H*W)` or `(B,H*W,C)`, and records the launch metadata for use by the backward conversion kernel.
