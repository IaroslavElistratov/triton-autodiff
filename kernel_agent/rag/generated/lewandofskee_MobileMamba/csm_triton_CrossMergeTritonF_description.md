- kernel family: Cross-state merge (summing multi-directional 2D scan outputs)
- concise summary: The forward launch tiles the (height, width, channel) space and, for each block, gathers up to four directional scan buffers from `y`, summing them into the merged tensor `x` according to layout and scan-count settings.
- detailed summary: `triton_cross_scan_flex` runs on a 3D grid `(NH*NW, NC, B)` where each program handles one spatial tile `(BH×BW)` for a channel chunk `BC` and batch `B`. It precomputes index routes (`HWRoute0-3`) that map from the tile to four traversal orders (top→bottom, left→right, and their reverse counterparts) while masking out-of-bounds positions when the image edges are smaller than the tile. In the forward configuration (`operation=1`, `onebyone=0`), the kernel walks every channel in the chunk, loads the four directional accumulators from `y` (whose layout depends on `out_channel_first`), and writes their sum back into the destination layout (`in_channel_first` or not). The host wrapper `_CrossMergeTritonF_forward` derives tiling parameters (`BH=BW=32`, `BC=1`), allocates the output buffer in either merged `(B,C,H*W)` or per-pixel `(B,H*W,C)` format, remembers the launch-time metadata on the context, and dispatches the Triton kernel with the provided scan-count so only the required route indices are used.
