- kernel family: fused MLP (dense → squared-ReLU → dense) with Triton GEMM tiling and optional activation checkpointing
- concise summary: The forward path flattens the batch, launches a Triton matmul that computes `x @ weight1^T + bias1`, optionally saves that activation tilewise, applies squared-ReLU in-kernel, and finally feeds the activated output into a second linear layer, sharing checkpoints based on the requested recompute level.
- detailed summary: `kernel_fwd` maps a 2D grid of programs over output tiles: each program picks BLOCK_M×BLOCK_N tiles, streams through K in BLOCK_K chunks, and accumulates the dot-product with layout-aware pointer arithmetic for row-major inputs and column-major weights. It can fuse bias loads, optionally spill the pre-activation tensor for backward, and apply one of several activations (squared-ReLU in this function) entirely in registers before writing the tile back. `triton_linear_act` prepares contiguous views, creates output and optional activation buffers, and autotunes launch parameters using numerically aware heuristics. The autograd forward wrapper selects either the Triton path (allowing activation reuse or recomputation depending on `checkpoint_lvl`) or a fused CUDA implementation for bf16 inputs; it materializes the first-layer output, applies squared-ReLU, launches the second dense layer, and records whichever intermediates are needed for backward without ever touching the backward kernels.
