- kernel family: cross-entropy loss (row-wise log-sum-exp with label smoothing, z-loss, and distributed class sharding)
- concise summary: The forward Triton kernel processes one logit row per program, streams the vocabulary in `BLOCK_SIZE` chunks to build a stable log-sum-exp (unless precomputed), applies optional label smoothing/logit scaling/z-loss, and writes per-row losses while caching the log-sum-exp for backward or multi-rank reduction.
- detailed summary: `cross_entropy_fwd_kernel` loads each tile of logits, multiplies by `logit_scale`, and updates running `m_i`/`l_i` accumulators to form the row log-sum-exp; when `HAS_SMOOTHING` it also accumulates the sum of logits for the smoothing term. After the reduction it fetches the label index (adjusted for the rank’s class shard) and constructs the loss—either `lse - logit[label]` or the smoothed variant—and, when not in “split” mode, adds the optional `lse_square_scale * lse²` term while writing both loss and z-loss buffers. The Python launcher handles layout (making logits contiguous if needed), chooses `BLOCK_SIZE`/`num_warps` from the column count, allocates per-row loss/LSE/z-loss tensors, and dispatches one program per row. In distributed configurations it gathers the per-rank LSEs, performs a host-side log-sum-exp/all-reduce to combine losses across ranks, recomputes the z-loss if requested, masks `ignore_index`, and stores the logits/LSE/labels for the backward pass.
