- kernel family: addmm (matrix multiply plus bias)
- concise summary: Provides Triton addmm kernels that tile the M×N output, accumulate X·W in fp32, add either a row or column bias, and optionally use persistent TMA descriptors with warp specialization for H100-class GPUs.
- detailed summary: The standard `_addmm_fwd` kernel maps program IDs to (m,n) tiles, loads BLOCK_K chunks of X and W with masking for ragged tails, performs `tl.dot` with optional TF32, and fuses the bias addition—either loading a broadcast 1-D bias or a 2-D bias slice—before storing the tile. A persistent variant uses tensor descriptors, iterates tiles in a for-loop stride of NUM_SMS, and can warp-specialize the loop to improve residency. The Python wrappers choose between the Triton kernels and the PyTorch fallback (for SM100 or HIP), build the launch grid, and handle descriptor setup, bias reshaping, and alignment checks before returning the fused addmm output.
