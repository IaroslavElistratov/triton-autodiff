- kernel family: batch normalization (feature-wise statistics with optional residual and fused activation)
- concise summary: Each Triton program owns one feature channel, performs a two-pass sweep over the batch×spatial volume to compute running mean/variance, optionally updates running stats, then normalizes the channel, applies affine weights, adds a residual, and can invoke a fused activation while caching intermediates.
- detailed summary: `batch_norm_forward_kernel` uses autotuned tile sizes (`BLOCK_SIZE_BATCH`, `BLOCK_SIZE_SPATIAL`) to iterate over the batch and spatial axes. During the statistics pass it loads fp32 tiles, updates a running mean/variance via incremental formulas, and stores the per-channel `mean`/`inv_std` buffers when gradients are needed. If tracking stats during training, it writes exponential moving averages into the provided `running_mean`/`running_var` using the configured `momentum`. In the second loop it reloads the tiles, applies `(x - mean) * inv_std`, multiplies by `weight` and adds `bias` when `affine` is enabled, optionally accumulates a residual `pre_act_add`, and conditionally calls `apply_act_func` to fuse activations (saving the pre-activation slice if requested). The Python launcher coerces the input and optional residual to a `[batch, feat, spatial]` layout (transposing if needed), allocates scratch buffers for saved stats, selects a grid of one program per feature, and reshapes the normalized output back to the original view.
