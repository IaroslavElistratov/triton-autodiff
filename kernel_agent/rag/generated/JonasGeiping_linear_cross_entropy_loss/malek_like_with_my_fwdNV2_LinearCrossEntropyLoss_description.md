- kernel family: loss (Malek-style chunking with multi-tile vocab streaming and CPU-side gradient assembly)
- concise summary: Tiles each chunk of activations against `Aᵀ`, fills a reusable `(chunk,V)` buffer while tracking per-block losses and log-sum-exp, then converts those logits into probability residuals via a Triton prologue before using dense matrix multiplies to populate `x` and `Aᵀ` gradients.
- detailed summary: `linear_xent_fwd_prep_bwd_kernel_matmul_t` divides the vocab dimension into `V_TILES × V_BLOCK_SIZE` groups so each program streams several contiguous tiles, writing raw logits into `z_nv_and_grad` and accumulating loss contributions and log-sum-exp slices in `losses`/`lse_local`. After each chunk the host inspects the chosen autotune configuration to determine how many columns were populated, reduces `lse_local` accordingly, and, when gradients are needed, launches `linear_xent_mini_bwd_prologue_kernel` to overwrite the logits with `(softmax(z-lse) - one_hot)/N`. These residuals are then handed to dense BLAS calls: a matrix multiply (`z_grad @ Aᵀᵀ`) fills the chunk of `x_grad`, while `torch.addmm` combines `z_gradᵀ` with the original activations to accumulate `A_grad`. The forward pass therefore leverages Triton for numerically stable logit generation and probability conversion, but outsources the final gradient contractions to highly optimized GEMMs, keeping memory usage bounded by the chunked buffers while still avoiding full recomputation.
