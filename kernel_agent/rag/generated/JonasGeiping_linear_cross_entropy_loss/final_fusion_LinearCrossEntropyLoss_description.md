- kernel family: loss fusion (end-to-end fused linear projection + cross-entropy with immediate epilogue gradients)
- concise summary: Processes the batch in `N_chunk_size` groups, uses a Triton matmul kernel to stream logits into a scratch buffer while accumulating per-block losses and log-sum-exp tiles, and—still inside the forward pass—launches specialized epilogue kernels that transform those logits into `x` and `Aᵀ` gradients when required, leaving only compact statistics for the autograd backward.
- detailed summary: `linear_xent_fwd_prep_bwd_kernel_matmul_t` (not shown in full above) is invoked per chunk with a 2D grid over `(batch tiles, vocab group tiles)`. Each program multiplies its `N_BLOCK_SIZE × H_BLOCK_SIZE` activation tile with matching slices of `Aᵀ`, writes the resulting logits into the `logits` staging tensor, and updates a running max/exponent pair to produce log-sum-exp vectors recorded in `lse_local`. It also reduces the ground-truth logits into `losses` so the host can sum cross-entropy contributions without keeping the entire `(N,V)` matrix alive. After each chunk, the host reduces `lse_local.logsumexp(1)` to complete the normalization and, if gradients are needed, immediately calls `linear_xent_bwd_kernel_matmul_t_epilogue_dx` and `_dA`. Those epilogues revisit the cached logits, apply `exp(z - lse)` minus the one-hot labels, and tile-wise accumulate the input/weight gradients, respecting autotuned group swizzling to balance occupancy. By performing these epilogues under `torch.inference_mode()`, the forward routine fuses projection, log-softmax, loss summation, and gradient formation in a single streaming pipeline; the backward hook later only rescales the saved `x_grad` and `At_grad`, meaning the forward stage fully captures the compute-heavy portions while keeping memory confined to chunk-sized logits and statistics.
