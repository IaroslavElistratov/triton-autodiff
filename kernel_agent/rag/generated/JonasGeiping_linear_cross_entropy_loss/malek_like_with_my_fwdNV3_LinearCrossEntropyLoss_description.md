- kernel family: loss (Malek-style fusion with Triton epilogues for both gradients and multi-tile vocab scheduling)
- concise summary: For each `N_group` slice, a multi-tile Triton kernel builds logits and per-block loss statistics, after which dedicated Triton epilogues immediately transform those logits into `x` and `Aᵀ` gradients—so the forward pass returns both the scalar loss and fully assembled gradient tensors.
- detailed summary: The forward kernel `linear_xent_fwd_prep_bwd_kernel_matmul_t` swizzles across `(batch tile, vocab tile)` and supports autotuned `V_TILES`, streaming a configurable number of vocabulary blocks per launch while writing logits into a chunk buffer and populating `losses`/`lse_local` with numerically stable reductions. After each chunk, the host reduces `lse_local.logsumexp(1)` to add into the running loss, and if gradients are required, calls `linear_xent_bwd_kernel_matmul_t_epilogue_dx` and `_epilogue_dA`. These epilogues revisit the staged logits, compute `softmax(z-lse) - one_hot`, and tile-wise accumulate into `x_grad` and `At_grad`, using swizzled program grids to balance work across the batch, hidden, and vocab dimensions. The forward routine prints the selected Triton configs for tracing, caches the gradient tensors, and returns the total loss (including the partial sums from `losses` and the log-sum-exp). This variant therefore keeps chunked logits resident only long enough to feed the Triton epilogues, producing gradients eagerly without handing control back to autograd.
