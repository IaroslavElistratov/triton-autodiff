- kernel family: loss fusion (production-ready split-N/V epilogue with fixed reduction)
- concise summary: Requires tidy 64/128 multiples, stages logits and log-sum-exp slices per chunk, and uses a split-N/V gradient dispatcher that supports optional z-regularization and fp32 accumulation while treating every token as valid (reduction = N).
- detailed summary: The forward kernel tiles `(N,H)` activations against `Aᵀ`, stores logits into a scratch buffer, and writes block-level losses plus log-sum-exp entries. Because `reduction` is set to `N`, the loss and gradient normalization always assume every row contributes (ignore indices are zeroed later); this simplifies scaling for deployment. After each chunk the host computes `lse_global`, adds it to the running loss, and, if gradients are requested, launches `linear_xent_bwd_dispatcher` with the autotuned `SPLIT_N/SPLIT_V` factors. Those epilogues either revisit the staged logits to compute `softmax(z-lse) - 1/N` with optional z-regularization before dotting with `Aᵀ`, or multiply activation tiles by the staged gradients to accumulate weight updates—optionally in fp32 depending on the class attribute. Running under `torch.inference_mode()`, the forward pass exits with cached `x_grad`/`At_grad` tensors while returning the summed loss, making this “usable” variant suitable for production flows where reductions and shape constraints are standardized.
