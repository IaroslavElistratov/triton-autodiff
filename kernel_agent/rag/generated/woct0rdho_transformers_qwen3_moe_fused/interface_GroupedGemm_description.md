- kernel family: grouped GEMM (expert-wise tiling with shared input batches)
- concise summary: The forward interface launches a Triton kernel that walks over experts, slices the input rows according to `m_sizes`, and computes `X_e @ W_e` tile-by-tile so heterogeneous expert batches can share a single matrix multiply call; companion kernels support the transposed pass and weight-gradient accumulation.
- detailed summary: `_GroupedGemm_forward` calls `grouped_gemm_forward`, which validates contiguity and shapes (`X` is [M,K], `W` is [E,N,K], `m_sizes` holds per-expert row counts). The Triton kernel `_grouped_gemm_forward_kernel` assigns one program stream per SM, iterates over experts, derives the row range `[m_start,m_end)` for each expert, and processes the associated tiles (BLOCK_M × BLOCK_N × BLOCK_K) with standard dot-product accumulation, writing results back into the contiguous output matrix. Additional kernels provide support for transposed GEMMs and weight gradients: `_grouped_gemm_backward_dw_kernel` loops over N/K tiles accumulating `Yᵀ·X` into the expert weights, while `_grouped_gemm_forward_transposed_kernel` targets scenarios where the expert weights are stored transposed. These primitives underpin higher-level LoRA/MoE ops by reusing the same grouped-tiled GEMM logic.
