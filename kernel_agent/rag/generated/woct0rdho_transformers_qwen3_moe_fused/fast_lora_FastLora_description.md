- kernel family: fused LoRA + grouped GEMM (expert-aware matmuls with optional 4-bit weights)
- concise summary: Forward builds three LoRA-projected matmuls (G, U, W) on top of a grouped expert GEMM, applies a SiLU gate, and supports per-expert block quantization by dequantizing on the fly when quantization states are provided.
- detailed summary: `_FastLora_forward` first harmonizes dtypes and (if quantization metadata is present) flags the weight tensors so `_maybe_dequant` can reconstruct FP weights when needed. The helper `grouped_gemm_forward` launches `_grouped_gemm_forward_kernel`, which iterates over experts, uses `m_sizes` to pick the row ranges assigned to each expert, and executes tiled GEMMs (BLOCK_M/N/K) against the expert’s weight slice—skipping experts with zero rows and reusing the GPU SM count for persistent tiling. `mv_lora` wraps this GEMM: it optionally dequantizes the low-rank weight (`_maybe_dequant`), performs the base projection, and adds the LoRA update `B·(A·x)` scaled by `S`. Forward computes two such projections (`e` and `g`), combines them via `silu_mul_forward` (a tiny Triton kernel that applies SiLU to `e` and multiplies by `g` elementwise), and feeds the result through the output LoRA block to obtain `y`. The context stores the quantized weights/scales and the intermediate activations (`e`, `g`) for the custom backward routine.
