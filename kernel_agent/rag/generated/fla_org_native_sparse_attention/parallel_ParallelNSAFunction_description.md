- kernel family: block-sparse attention (per-token block selection with grouped heads)
- concise summary: Consumes precomputed block indices to gather causal key/value tiles, applies softmax-normalized attention within grouped heads, and emits the fused value output alongside log-sum-exp terms.
- detailed summary: Each Triton launch uses grid (T, ceil_div(V,BV), B·H), so a program instance owns one token, one value tile, and one batch–head. Optional ragged batches reuse `token_indices` to remap token IDs before arithmetics; dense batches compute offsets analytically. Inside the kernel the query slice is scaled and loaded, then the program iterates over the token’s allowed sparse blocks: `block_indices` supplies block IDs, `block_counts` (scalar or tensor) limits how many entries to visit, and each block spawns block pointers that fetch a BS×K key tile and a BS×BV value tile anchored to the head’s region. Scores are computed with dot products, masked to enforce causality (`i_s*BS` ≤ current token) and range checks, and fed into a log-sum-exp reducer that maintains running maxima (`b_m`) and denominators (`b_acc`). After processing all permitted blocks, the accumulated value mixture is normalized by `b_acc`, the output tile is stored, and per-group log-sum-exp values are written through `lse`. Autotuning picks warp counts and tile sizes (`BK`, `BV`) subject to hardware capabilities, while the Python launcher materializes outputs and prepares per-token metadata ahead of the kernel call.
