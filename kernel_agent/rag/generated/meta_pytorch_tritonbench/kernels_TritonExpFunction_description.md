- kernel family: elementwise activation (exponential with profiling hooks)
- concise summary: Launches a 1D Triton grid where each program handles a contiguous block of elements, loads the input, applies `tl.exp` elementwise, and stores the result into a preallocated output buffer, optionally recording per-program runtime counters.
- detailed summary: The forward driver precomputes the total number of elements, derives a grid size via `cdiv(n, block_size)`, and allocates the destination tensor ahead of the kernel launch so the Triton kernel can write densely. Inside `triton_exp_kernel`, each program id computes its start offset, forms a range of block indices, masks out-of-bounds lanes, and performs a single fused load-compute-store trip using `tl.exp`. When a `profile_mem` tensor is supplied, the kernel also invokes the platform-specific `time()` helper to capture cycle counts per program id, writing them back to global memory to enable host-side profiling of memory latency overlap. The forward path therefore stresses memory bandwidth while leaving shape-dependent parallelism entirely to the block size choice.
